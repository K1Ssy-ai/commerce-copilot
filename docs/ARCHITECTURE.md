## 初版边界

首版计划采用虚构商品和订单数据，只验证业务查询流程。[ADR-001](TECHNICAL_DECISIONS.md) 记录了 Python 3.12 标准库、命令行入口、显式查询路由与 JSON 只读数据的初步方案；尚未实现。LangGraph、FastAPI、SQLite 与向量检索留待相应需求出现后评估，不是当前已安装或已验证的项目依赖。

1. **交互层**负责收集问题、展示结果和明确提示当前演示范围。
2. **编排层**负责选择业务模块、传递有限上下文并收集执行结果。
3. **业务层**暴露显式输入输出的查询接口，不接受任意 SQL 或未验证的状态变更。
4. **数据层**管理商品、订单与政策示例。订单查询必须绑定当前客户身份。
5. **确认层**在后续写操作中独立保存提案、确认与执行状态。

## 后续关键决策

- 是否从最简单的显式路由开始，再引入多智能体编排。
- 商品价格与库存采用何种口径；何时以业务系统结果为准。
- 订单身份如何传入，如何验证订单属于当前客户。
- 政策失效、冲突或检索无结果时如何回复。
- 操作确认后上下文改变时，是否使原提案失效。
- 在许可确认前，如何保持实现独立且来源可追踪。
